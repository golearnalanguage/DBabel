# Source and evidence policy

## Principle
Authority depends on what is being verified. DBabel uses a dynamic hierarchy, not a global website ranking.

## Primary source classes

### Standards/specifications
Use the responsible standards/specification body when the candidate is standards-defined. Examples of source classes include ISO/IEC, IETF, W3C, Unicode, NIST and other competent standards bodies according to topic.

### Vendor/product sources
For vendor-specific terminology, prefer the same vendor, same product, and same version official documentation or official UI. Release notes and versioned manuals may be required when naming changed over time.

### User-provided official material
If the user provides an official product manual, approved bilingual guide, UI reference, or project glossary, use it within its stated scope and record its provenance.

### Reputable terminology/reference sources
Use for general terminology or triangulation. Do not allow them to override an official product name merely because they are multilingual.

## Secondary/discovery-only sources
Search-engine snippets, community forums, Q&A sites, blogs, reseller pages, machine-generated summaries, and social media may identify leads but are not sufficient final evidence for a material vendor-specific replacement when primary sources are reasonably available.

## Evidence adequacy dimensions

- `authority_match`
- `vendor_match`
- `product_match`
- `version_match`
- `context_match`
- `text_role_match`
- `recency_or_version_relevance`
- `directness`
- `conflict_state`

## Evidence lifecycle
Record retrieval date and source/version metadata. A previously valid source can become stale after product/version changes. Do not silently reuse an old finding as timeless truth.

## Citation discipline
Cite/open the underlying source document, not merely a glossary aggregator or search result, when the underlying source is available. Preserve minimal evidence necessary to support the decision.

## Recorded evidence
Use unique IDs and include the source records in the report. CURRENT means
applicable to the reviewed scope, not necessarily the newest publication.
An approved project rule supports project wording, not a claim of official vendor
usage. If that distinction is material, record it explicitly before adjudication.
