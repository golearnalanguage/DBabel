# B5 NULL、空字符串与“未知”被混成一个概念

合成诊断案例；不得作为实际产品证据。只有人工审核者能批准修改。

**模式：** LOOKUP、BILINGUAL_REVIEW。
**输入：** 本例已读、适用的参数与 SQL 说明规定：NULL 与空字符串不同；标量值的普通等号比较涉及 NULL 时结果为 unknown。待审译文：“NULL 表示空字符串，因此 NULL = NULL 为真。”

**问题成因：** 把自然语言的“空”映射到多个不同技术概念；将日常“相同东西相等”的直觉套入 SQL 三值逻辑。

**排查与判断：**

1. 分别列出 NULL、空字符串、数字 0、文本字符串 `'NULL'`，查明材料讨论的数据类型与产品范围。
2. 对照给定定义，区分缺失值、已知的零长度字符串和普通字符串文本；不要只用一个“空值”统称。
3. 确认使用的是普通等号还是专门的空值判断／空值安全比较；不同运算不能互相代替。
4. 将三种真值 true、false、unknown 分开。这里普通等号比较结果不是 true，也不能简单改成 false。
5. 若文档涉及特殊兼容模式、复合值或另一产品，重新核查对应语义，不推广本例结论。

**处置：** 在给定范围内，将译文 `REPLACE` 为“NULL 不等同于空字符串；使用普通等号比较 NULL 时，结果为未知。”保留 SQL 标记，不把说明审校扩展成查询重写。产品范围或运算符不明时，相关概念判断 `REVIEW`。

**验收：** 能说清“哪一种空”“哪一种比较”；不把 unknown 译成 false，不给 NULL 加引号变成字符串，不宣称所有数据库对空字符串的处理都相同。
