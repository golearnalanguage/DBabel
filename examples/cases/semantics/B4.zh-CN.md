# B4 术语修正与性能主张分别处理

合成诊断案例；不得作为实际产品证据。只有人工审核者能批准修改。

**模式：** AUDIT、CLAIM_ROUTE。
**输入：** 项目词表规定“事务处理速率”使用 transaction throughput。待审句：

> Our transaction speed is twice that of the baseline, with no data loss.

只提供了术语表，没有测试方法、负载、硬件、故障条件或测量结果。

**问题成因：** 把术语顺畅误当作事实可靠；润色时可能进一步扩大“无数据丢失”的承诺。

**排查与判断：**

1. 分开定位术语 transaction speed、倍数比较 twice、保证性主张 no data loss。
2. 术语按已批准词表处理；保留原倍数含义，不能把 twice 写成增加 200%。
3. 对倍数和保证分别说明需要什么证据；不能用词表支持测试结论。
4. 检查原始材料是否有适用负载、同步模式、故障范围等限定，防止漏译或移出有效范围。

**处置：** 术语 `REPLACE` 为 transaction throughput；两个事实主张分别 `OUT_OF_SCOPE_CLAIM`，classification 为 `TECHNICAL_CLAIM`，明确 next_action。若用户另要求事实核查，按独立证据任务处理；未核实前不强化，也不自行删除原主张。

**验收：** 每个问题有独立位置与决策；修改术语的记录不写成“性能和可靠性已验证”。
