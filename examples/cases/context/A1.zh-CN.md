# A1 标题写“导出”，实际步骤描述“导入”

合成诊断案例；不得作为实际产品证据。只有人工审核者能批准修改。

**模式：** AUDIT、BILINGUAL_REVIEW。
**输入：** 技术手册片段；附带的工具说明确认 export_tool 生成归档、import_tool 读取归档并装载目标库。

```text
一级标题：数据迁移
  二级标题：1 源端准备
    三级标题：1.1 导出数据
    操作：从源库生成 archive.bin。
    命令名称：export_tool
  二级标题：2 目标端装载
    三级标题：2.1 数据导出
    操作：读取 archive.bin，将数据写入目标库。
    命令名称：import_tool
```

**问题成因：** 复制上一节的小标题后未更新，或步骤被移动后标题与正文脱节；不能仅凭表面词义断定是哪一处错了。

**排查与判断：**

1. 确认 2.1 的父标题是“目标端装载”，不是仍属于“源端准备”。
2. 跟踪同一文件：1.1 生成 archive.bin；2.1 读取该文件。比较动作的起点、终点与输入输出。
3. 对照本例提供的工具说明，核查命令实际承担的动作；不能只凭工具名称猜功能。
4. 搜索同章步骤表、图注和交叉引用，检查是否有第二次导出、回滚或校验分支。流程不必按“导出—导入”交替。
5. 记录支持“导入”的证据及仍然冲突的小标题；如资料仍不足，保留原文并请求针对性确认。

**处置：** 2.1 小标题标 `REVIEW`；提出候选“数据导入”，说明需确认标题是否复制错误。命令名称 `PROTECT`，不把 import_tool 改成 export_tool。得到源文更正依据或明确确认后，才对该标题提出 `REPLACE`；同步检查目录和引用该标题的位置，逐处留痕。

**验收：** 说明“为什么怀疑标题”，列出父标题、数据流及命令依据；不能只写“上一步导出，所以下一步必然导入”。只有英文把正确的“数据导入”错译成 Export 时，才直接按源目标不一致提出译文修正。
